# Review: retire the expandable writing margin

Date: 2026-10-03. Status: historical design review; implementation is recorded in the follow-through below, ADR 016 and the canonical plan. Inspected HEAD `4763414` plus the existing uncommitted writing-area, margin and sync changes. Those changes are part of the reviewed baseline, not changes made by this review.

## Confirmed scope

The owner wants to remove the expandable note margin that narrows the book text, now that handwritten notes have resizable writing areas. Keep the Narrow/Normal/Wide reading-margin settings and their configuration policy. This supersedes the requirement to offer expandable margin writing; it does not authorize deleting existing annotations.

Recommendation: retire margin authoring while retaining the old data format and a compact note viewer. Offer an explicit, undoable **Move into Text** operation for old margin notes before removing their existing editing route. Do not automatically rewrite a library on open. This conversion policy is a recommendation, not yet an owner decision.

## Findings

| Issue | Evidence and implication |
| --- | --- |
| Margin code also serves ordinary notes on small screens | `InkEngine.render` sends both margin notes and ordinary notes on narrow columns to `MarginLayer`. `InkMarginControl` reserves their icon gutter, and `MarginNoteSheet` displays both. `FoliateManager.#flowNotesAsIcons` uses a 480 pt column threshold. Deleting these components would also remove the existing iPhone/Split View viewing path for resizable notes. Keep this behavior and separate it from expansion. |
| Saved margin notes cannot simply become writing areas | `InkNote.placement == .margin` and `refWidth` describe margin notes. Strict decoding rejects an `area` on a margin note; `InkOperation.setNoteArea` and `InkSession` also exclude them. Removing the fields or enum would make existing payloads unreadable. Preserve decoding, encoding, sync, export and restore support, including notes arriving later from an offline device or old backup. |
| Conversion changes placement semantics | An inline note is inserted before its anchor; a margin note sits beside its anchored line. Conversion changes pagination and may place the note before a passage instead of alongside it. Margin strokes can extend left into the text. Derive an area from the full painted bounds and original width; do not just clear `placement` or rebase the strokes. Keep the same note ID, anchor/edition evidence, creation time and stroke values. |
| Concurrent edits can reverse a conversion | `AnnotationSync.merge` unions strokes but takes the other note properties from the version selected by the sync clock. An offline device's later margin edit can therefore restore margin placement. Keep legacy records reachable and test this outcome; a permanent one-way conversion would need a separately documented conflict rule. Stroke values must remain unchanged because merge identities derive from them. |
| Removing the toolbar button alone does not remove expansion | `MarginOpenMemory` restores an open margin per book, icon taps open it, and `inkFocusMarginNote` opens it for the sheet's editing action. All these entry points must be retired together. The old preference can initially be ignored; it is local view state, excluded from configuration sync and backup. |
| The existing editor would become a dead end | The note sheet's **Edit This Note in Margin** selects the old margin drawing for lasso editing. Replace it with a working conversion/edit route before removing that capability. Keep full drawing, passage context, confirmed deletion, annotation browsing, export and orphan recovery. Icons for old margin notes should open the viewer directly on every screen. |
| Resizable areas do not reproduce every margin behavior | They occupy text flow, only wrap text when enough width remains, and fit tall areas within 85% of page height. On narrow screens they still become icons. They do not provide a continuous blank rail down the page. Accept that product change explicitly; tall and crowded legacy notes require visual checks after conversion. |
| Replacement acceptance is incomplete | ADR 015/BF-081 records iPad simulator evidence, but real Pencil, VoiceOver, manual undo/redo, landscape spreads, Mac/iPhone rendering and signed two-device iCloud acceptance remain open. Removing the older workflow does not close those gates. Area payloads need feature level 2; its Production CloudKit schema deployment is also a recorded release prerequisite. |

## Recommended increments

1. **Separate shared note viewing from expandable writing.** Preserve the icon gutter, grouping/hit testing, tap suppression, sheet, full drawing, status-band clearance and narrow-column projection. Rename internal margin-specific viewer concepts only where touched; avoid a broad rewrite. Add coverage proving ordinary notes and empty writing areas remain reachable when expansion is disabled.
2. **Provide the legacy-note editing transition.** Add a Kit-owned, single-note conversion through the existing durable mutation/session path, with one undo step and retained recovery evidence. Validate the note and current revision; preserve raw stroke coordinates and identity. Choose area width/side from drawing evidence, including negative extents, and preserve unresolved anchors without guessing. Preview the layout before committing. Specify restore, rollback and concurrent-edit behavior in an ADR before implementing the conversion. An alternative is legacy viewing only, but that intentionally removes editing of old notes and needs an explicit product decision.
3. **Retire expansion end to end.** Remove the toolbar toggle, automatic reopening, focus/open commands, margin-writing classification and open-margin CSS. Simplify the page-state controller while retaining gutter presence and narrow-column changes. Route legacy icons straight to the note viewer and its conversion action. Keep all reading-margin settings, margin taps for page navigation, and bracket marks.
4. **Keep compatibility and verify.** Retain `placement`/`refWidth` in protected reads and round trips. Old records can return through sync or restore indefinitely; no local inventory proves support can be deleted. Do not bump or remove a schema merely to hide a UI feature. Update the canonical Phase 5 scope, architecture, interaction decisions and acceptance checklist with implementation evidence when each increment lands.

This can end with no expandable margin in the product while retaining a small compatibility layer. Deleting the stored format is unnecessary to accomplish the owner's goal. No new persistence path, cloud record kind or third-party engine is required by this recommendation.

## Validation required for implementation

- Portable tests: old margin payload round trips; late sync and backup restore; conversion retains ID, anchor, creation time, stroke hashes and count; invalid/unknown data is protected; failed save, restart, stale revision, undo/redo, concurrent edits and delete-versus-edit retain recoverable work.
- Renderer tests: expansion cannot be reactivated by remembered state, icon taps or focus calls; new writing stays in text/areas; legacy and ordinary note icons remain reachable; gutter clearing, overlapping icons, long drawings, negative coordinates, status-band clearance, scroll mode, portrait/landscape and resizing preserve ink. Retain relevant coverage from `inkMargin`, `inkMarginControl`, `inkNarrowColumn`, `inkArea`, selection and anchoring tests instead of deleting whole suites.
- Isolated simulator usability: large and mini iPads plus iPhone, synthetic mixed legacy/inline/empty-area book; open/view/convert/edit/cancel/delete/undo/reopen; Narrow/Normal/Wide, landscape, scrolling and narrow layouts; navigation, labels, accessibility semantics and reading-position continuity. Record device/OS/build, actions and limitations.
- Mac viewing/build and portable checks; Apple component tests with an explicit isolated simulator and verified result inventory. Real Pencil/palm/VoiceOver and signed two-device sync remain distinct release gates. Verify a restored old backup and an offline older device cannot make a note disappear or duplicate its strokes.

## Review evidence and limitations

Read architecture, contribution guidance, annotation review, canonical plan, Phase 5 backlog, Pencil decisions, ADR 015 and the related implementation/tests. No personal annotation store was inspected and no assumption was made about how many legacy notes exist. No app behavior or annotation data changed.

No Swift build, simulator workflow, hardware or signed-cloud test was run for this design review. No bugfix was implemented, so no BF entry is added.
