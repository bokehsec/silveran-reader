# ADR 007: Protect configuration originals and retain unsaved local preferences

- Date: 2026-09-30
- Status: Accepted for the existing configuration owner; complete archive/restore remains gated
- Scope: Kit settings persistence/patch validation, Apple recovery presentation and preference publication
- References: [plan P3.1/P3.3](../ANNOTATION_SYNC_BACKUP_IMPLEMENTATION_PLAN.md), [field inventory](../ANNOTATION_CONFIGURATION_FIELD_INVENTORY.md), [BF-022](../../BUGFIX_LOG.md#bf-022--protect-configuration-originals-and-retain-failed-local-edits)

## Decision and alternatives

Keep `SettingsActor` and the current unversioned global configuration JSON layout. Add a protected persistence/archive codec in front of the existing model decoders. Tolerant public decoders remain useful for existing renderer/network callers, but cannot establish permission to overwrite persisted data. Moving configuration into SQLite just for backup would change unrelated ownership and would still not commit UserDefaults/fonts/source state together; it is not selected. Accepting a partially decoded file and writing the projection would silently remove creative themes or future settings and is rejected.

Initialization performs no writes or directory creation. Report missing, valid, corrupt, unsupported and unreadable separately, retaining exact readable original bytes. Defaults permit reading in recovery states, never mutation of the original. Before every commit, read and validate the current file and require its bytes to match the owner's observed original. External valid changes require explicit rereading; unreadable/damaged/unknown data blocks writeback, including no-op remote patches. This is one actor's ownership guarantee, not a filesystem lock against an unrelated process writing between the check and atomic replacement.

## Shape, aliases and legacy policy

Derive known field names/types from the owned models and declare nullable fields and theme/default policies separately. Refuse unknown keys at every level, wrongly typed present values, boolean/number substitution, nonnullable nulls, duplicate theme IDs, missing required editable theme fields and unsupported closed values that existing normalization would otherwise coerce. Preserve all theme fields and array ordering. Known missing fields retain documented defaults; partial legacy playback sections fill only missing known values rather than defaulting the whole section.

Recognize canonical model keys and their Foundation-generated snake-case forms explicitly, including CSS acronyms. Refuse both forms appearing for one field. Retain known legacy justify/scrolling/underline/TV conversions and legacy theme-label/appearance defaults. Open string preferences that the model preserves remain preserved; closed values that would be silently replaced are refused. Future schema fields remain original recovery data rather than an empty configuration.

Foundation remains the JSON grammar, key-string and Unicode decoding authority. A narrow lexical pass checks raw object-key uniqueness, including escaped equivalents, because dictionary decoding otherwise retains one value. It checks the entire input and bounds nesting; it does not provide another JSON domain decoder. Unicode conversion uses maintained Foundation `String` decoders without lossy conversion, followed by validated UTF-8 JSON decoding. Tests include UTF-8 BOM and UTF-16/32 data. Runtime evidence showed this host's `JSONSerialization` rejecting BOM-prefixed UTF-32 produced by `String.data(using:)`, despite broader documentation; the codec therefore does not assume the raw parser accepts every documented byte encoding. Configuration JSON written by the owner remains UTF-8.

Context7 primary Foundation documentation was consulted for [key-decoding conversion](https://developer.apple.com/documentation/foundation/jsondecoder/keydecodingstrategy-swift.enum/convertfromsnakecase), [key-encoding conversion](https://developer.apple.com/documentation/foundation/jsonencoder/keyencodingstrategy-swift.enum/converttosnakecase), [typed decoding](https://developer.apple.com/documentation/foundation/jsondecoder), and [JSON serialization](https://developer.apple.com/documentation/foundation/jsonserialization). Shape validation reuses the existing portable `ConfigurationValue` type, keeping booleans distinct from numbers without adding another dependency.

The current 16 MiB refusal boundary and 128-level lexical nesting bound protect input processing; they are not device memory/performance acceptance results. Oversized originals remain retained/read-only. Full archive capture must classify unreadable required configuration as incomplete, and include unsupported/damaged raw recovery material deliberately.

## Pending edits, observations and publishers

Accepted failed local edits remain typed pending patches owned by the actor. Accumulate changed fields, let newer explicit local choices supersede them, and remove fields that return to already committed values. Keep committed configuration distinct from its editing projection. A remote-origin durable commit can update unrelated committed values while local pending fields remain available for retry. Local retry merges those fields into the latest committed generation. Do not publish pending fields or notify committed-change observers on write failure.

One nonsuspending owner snapshot returns committed configuration, original/load outcome, pending changes and save failure together. Editors use the presented editing projection as their comparison baseline, preserving both pending local choices and untouched incoming fields. Failure survives editor closure through the actor; reader/settings presentation offers retry and recovery export. The export contains exact original bytes, committed values, owner pending fields and a separate editor draft. It is a local diagnostic recovery packet, not a complete archive or a promise of process-loss survival after a failed write.

Settings publication checks local recovery/pending state before explicit device export or queued flush. It leaves existing account/quota/schema safeguards in place. Import still uses the owner; unreadable originals cannot be overwritten by an incoming preference patch. Preference sync remains separate from historical annotation/configuration backup. Full multi-owner restore still needs suspended publishers, retained checkpoints and application journaling.

## Compatibility, reversal and evidence

The startup flat-color conversion uses this owner's protected source inspection and generation check. The `flat-color-theme-v1` sentinel is advisory because earlier builds could write it after a failed conversion. A valid original lacking `themes` remains eligible even with an old sentinel; an explicit `themes` section is authoritative, including an intentionally empty array. Before converting, the filesystem owner retains exact source bytes under `Config/MigrationBackups/flat-color-theme-v1/<SHA-256>.json`, refusing an unreadable or hash-colliding checkpoint. Only a successful settings commit permits marking completion. A missing source stays unmarked. These recovery copies must be included as a separate participant in the full archive, with retention and restore verification; this local checkpoint alone is not historical backup. [BF-023](../../BUGFIX_LOG.md#bf-023--a-failed-flat-color-migration-can-advance-its-completion-sentinel) records failed-write and marker-retry evidence. The change does not alter the selected JSON engine or cloud authority.

The separate iPad Pencil tool preference retains its existing `SilveranInkTools.v1` UserDefaults key. [BF-024](../../BUGFIX_LOG.md#bf-024--protect-saved-pencil-tool-choices-from-tolerant-decoding-and-replacement) applies the same rule: a tolerant domain fallback is usable for display but cannot overwrite an unknown original. Kit owns strict decoding, pending choice and generation checks; AppleKit presents tool status/recovery. A UserDefaults write is checked by immediate readback and is never presented as a historical backup or fsync guarantee. This preference requires a dedicated full-archive participant and must preserve recoverable raw bytes when its schema is unsupported.

Supported settings retain their JSON location and fields; no engine, signing, account or cloud authority changes. Remove the adapter only with a compatible recovery strategy; returning to the old overwrite-on-failure behavior is unsafe. Pending data after unsuccessful writes is memory-only and exportable, not crash-durable. Missing originals are distinct from permission/I/O/invalid-parent failures.

`ConfigurationPersistenceSafetyTests` proves exact original preservation, full known-field/theme round trips, safe legacy aliases, wrong types, unknown fields, duplicate/escaped keys and Unicode encoding cases, failed-write accumulation/cancellation, remote merge, external-file changes, missing/unreadable distinction, export equality and nested generic-patch protection. `ConfigurationCoordinatorTests` exercises actual reader view-model failure/closure/replacement/retry and rejects explicit cloud publication of protected viewing defaults. Existing preference account/restart/outbox/merge tests remain required. Before/after failure reproduction and exact final checks are recorded in BF-022/the implementation plan.

No complete phase exit gate, real-device UI quality, full configuration asset recovery, signed account delivery, application cutover or historical cloud backup is established by this change. Owner/category enumeration and the remaining plan work continue.
