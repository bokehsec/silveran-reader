Date: 2026-10-02. IP-0 baseline and implementation contract, reviewed against the working tree at `6294e57bc3cf21ddb2e26cd7142906047bd19c40`. This records inspected paths and proposed protection; it does not claim failure-injection, simulator or signed-device acceptance. The starting working tree already contained changes to reader appearance/tools, ink writing groups, annotation diagnostics and CloudKit adapters, configuration sync, backup source descriptors, annotation tests and the canonical plan. ## Mutation inventory at baseline

| Path / owning boundary | Reads and durable writes | Suspension, notification and acknowledgement |
| --- | --- | --- |
| Local ink; `InkSession` → `InkActor.setSection` | Session captures a whole section; owner reads/reuses validated book and commits/removes its ink file. Session's pending sections and undo stacks are memory only. | Session serializes its persistence tail, but suspends before the owner call. Owner resolves path before read/commit and posts `LocalDataChangeSignal` after successful payload persistence. Session acknowledges saved only after success; no expected-section precondition at baseline. |
| Highlights/bookmarks/typed notes; `BookmarkActor` → `FilesystemActor.mutateHighlights` | Queued commands mutate protected per-book highlights. Failed commands remain in memory for retry/export. Placement repair checks an expected original in the protected owner. | Queue drain suspends at store and observer calls. Observers hear successful commits; raw owner protects unfamiliar fields. General `.update` is unconditional. |
| Incoming sync; `AnnotationSyncEngine.receive` | Reconciles owners, records clock/index, retains losing version, applies payload through owners, writes book sync metadata. | Engine's per-book lock excludes its own operations only. Owner application and snapshot calls suspend. Recovery/state write failures were suppressed. Owner notifications precede final sync metadata; app remote callback reloads open sessions. |
| Recovery-version application; `AnnotationSyncEngine.restore` | Retains current competing version, applies retained payload, reconciles into a fresh local sync change. | Same engine lock; no shared editor barrier. Failure retaining current version did not prevent replacement. |
| Placement repair; `AnnotationPlacementReview`, reader/library controllers | Typed repair uses owner `.repair(expected:replacement:)`; live ink uses `InkSession.apply`. Detached ink commits a section through owner. | Renderer/inspection awaits can stale a proposal. Typed owner compares atomically; ink whole-section persistence lacked equivalent precondition. Current/previous placement and raw quotations must remain. |
| Undo/redo; `InkSession` | Replaces whole section with stored before/after snapshot and persists it. | Stale snapshots can remove an independently arriving edit. Reload drops history, but baseline reload flushes pending sections first. |
| Identity move; `AnnotationSyncEngine.rehome` | Destination payload write, source payload removal, source/destination metadata and index writes. Retains competing versions through `keep`. | Sorts the two engine book locks; owner calls suspend. Three independent metadata saves follow payload removal. Failed source removal triggers best-effort destination rollback. No durable move intent at baseline. |
| Backup capture; `BackupService.capture` and participants | Reads legacy payloads, configuration, sources, shelves, fonts, preferences and configured recovery files. | Participants captured sequentially; no shared annotation snapshot generation. Sync recovery and identity state not registered at baseline. |
| Backup restore; `BackupService.restore/resume` | Retains archive and pre-restore safety snapshot, writes restore journal, applies participants through owners, records per-participant completion. | App flushes open ink and suspends configuration publisher. Annotation transport/edit acceptance remains active; restore resume reloads ink, whose baseline reload flushes first. |

## Durable-data inventory

| Data and current owner/location | Classification and reconstruction prerequisite | Backup/restore policy |
| --- | --- | --- |
| Editable notes/marks, highlights/bookmarks/typed notes and placement evidence; `InkActor` / protected highlights | Authoritative creative payload. Unknown/corrupt originals are authoritative recovery material, never an empty book. | Include originals and editable current payloads; validate raw schemas before applying. |
| Sync entry clock, content hash, deletion tombstone, prior stroke IDs, erased-stroke IDs, cloud book/scope; `Sync/Books` | Authoritative replication history. Payload scan can rediscover additions/changes, but cannot reconstruct deletion, erased-stroke intent, exact accepted clock or reversible cloud scope. | Preserve history; restore/rebind under explicit current-account policy, not automatic publication. |
| Global HLC; `Sync/clock.json` | Authoritative monotonic ordering evidence. Reconstruct only from all complete persisted entries/journals and verified remote history; payload alone is insufficient. | Preserve as evidence, validate device/account semantics; never replay as a user mutation. |
| Cloud-name → local-book index; `Sync/index.json` | Derived only when every book entry and pending journal is enumerable, valid and complete. Empty fallback is not reconstruction. | Rebuild from verified metadata; block if enumeration/history is damaged. |
| Losing payloads/tombstones; `Sync/Recovery` | Authoritative recoverable creative history, including unavailable books and original scopes. | Explicit lossless participant; enumeration/read failure makes capture incomplete. Restore aside, then explicit application. |
| Identity cards, established links, local translated/cloud scope evidence; `LibraryIdentityStore` | Established link and translation provenance are authoritative evidence; remote cards may be refetched only with correct account and complete remote records. | Retain original bytes; revalidate restored links before using account/edition equivalence. |
| Fingerprint cache; `LibraryIdentityStore` | Reconstructible only from available original assets with verified streamed SHA-256; size/time metadata does not establish content identity. | Cache optional; absent asset must remain unresolved, not guessed. |
| Incoming inbox and mutation/move journals (new protocol) | Authoritative unfinished accepted work and before/after evidence; never discard on startup/schema mismatch. | Include retained work as recovery material; do not resume old account transport automatically after archive restore. |
| Completed receive receipts; `Sync/Completed` | Redelivery/application receipts; reconstructible only from validated coherent Books and operation history, never from payload alone. | Include exact originals as recovery evidence; archive restore never installs them as live receipts. |
| CloudKit state serialization/change tags; Apple transport | Transport checkpoint, not creative data. Redelivery must be proven before advancing past local work. | Do not replay across accounts or fresh install. Rebuild only while all pending raw operations/history remain safe. |
| Restore journal/archive/safety copy; `BackupService` | Authoritative unfinished restore and recovery points. | Keep restartable archive and safety copy. Global annotation mutation barrier must persist/reestablish until resume finishes. |
| Session undo, pending strokes/sections, renderer geometry | Pending creative edits are memory only at baseline; geometry is derived from current asset/layout. | Pending work must be settled or retained durably before restore/close acknowledgement. Renderer caches need no backup. |

## Risks narrowed against actual code

R1 remains: `keep`, `write`, `loadState`, `loadIndex`, `loadClock` suppressed storage failures; receive could replace local work without durable recovery. Reliable isolated reproduction: reject writes to `Recovery` while receiving a newer conflicting highlight/mark or tombstone. Reject final `Books` metadata after successful owner mutation, restart and reconcile: baseline can invent a fresh clock for the received payload. Damaged `Books`, index or clock bytes fall back to missing history. Owner payload protection itself is already present; this review does not claim owners silently discard unknown payload fields.

R2 remains: pause a session persistence task, apply incoming ink to the same section, release the captured session task or call `reloadFromStore`; its unconditional section save can erase the remote item. Typed repair already has an atomic expected-original check, narrowing the repair risk. Whole-section undo still requires stale-history invalidation or intent-based commands.

R3 is partly implemented in pending work: automatic same-file/same-account matching, exact reversible translation and stable cloud record names exist. Interrupted rehome remains unsafe because source removal precedes metadata commit. Synthetic termination immediately after source removal reproduces missing move bookkeeping; destination collisions and unavailable owner snapshots require fail-closed handling. Shared new-source cards/onboarding work must be checked against current pending code, not assumed absent from the historical review.

R4 remains at baseline: `AppBackup` registers recovery only for `Config/MigrationBackups`; sync losing versions are omitted. `RecoveryMaterialBackupParticipant` used `try?` enumeration/read with an apparently successful empty capture. Baseline restore flush/configuration suspension does not quiesce annotation editors and receive/publication.

R5/R6 remain bounded follow-ups: inactive repository and active protected owners coexist; `LibrarySnapshot.current` branches on Storyteller when preparing server cards. Harden active ownership first; neither finding authorizes an opportunistic reader/database rewrite.

## Contract and fixture handoff

The [active protocol ADR](decisions/013-active-file-mutation-recovery.md) defines the durable ordering. First increment interfaces: injectable throwing production writes, explicit sync operation results, protected missing/valid/corrupt/unsupported reads, deterministic recovery identity, durable raw receive intent and resolved application journal, replay before reconciliation/publication, atomic owner expected-state checks, and restore suspension/drain hooks. A failed snapshot read is blocked; `nil` is never interpreted as a missing annotation.

Existing suites provide reusable synthetic owners: `AnnotationSyncTests`, `HighlightSyncCodecTests`, `CrossDeviceLibraryTests`, `InkSessionTests`, `HighlightPersistenceSafetyTests`, `AnnotationPlacementReviewTests`, `BackupParticipantTests` and `BackupRestoreTests`. `AnnotationCrashRecoveryTests` exercises the inactive repository and cannot alone establish the active protocol. Add fixtures at the actual active write seam for inbox/intent/recovery/payload/state/index/clock/completion failure, duplicate receive, restart after payload success, corrupt/future bookkeeping, delete/erase, repeated quotation and changed-edition translation, identity collisions, restore/receive and unavailable enumeration. Every fixture uses fresh temporary storage and synthetic source/book IDs; no user simulator or cloud reset.

IP-0 exit requires engineering-lead review of this contract, recorded portable baseline and active-path fault evidence. This document alone does not close the package.
